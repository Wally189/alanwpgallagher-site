# Alan WP Gallagher Site — Project Brief

## Status note

This project-control file was added on 2026-06-03 as a working-control layer for the existing `alanwpgallagher-site` repository.

It is based on the GitHub repository as seen at the time of setup. It may not capture local changes sitting in VS Code, uncommitted work, or unpushed branches. Those should be checked before making further content changes.

## One-line purpose

Build and maintain Alan WP Gallagher's personal website as a calm, credible professional profile and proof-of-work hub for business and technical operations, service improvement, process documentation, governance support and responsible AI-supported working.

## Primary audience

Hiring managers, recruiters, collaborators and organisations looking for practical operational, governance, project-support, service-improvement or technical-liaison capability.

## Secondary audience

People reviewing Alan's public projects, GitHub work, civic/voluntary work, website builds or AI-supported workflow examples.

## Positioning

This site should present Alan as a practical business and technical operations person, not as a generic administrator and not as an inflated software developer.

The professional story should sit around:

- business and technical operations support;
- service operations and service improvement;
- project coordination and documentation;
- process improvement and workflow tidying;
- Microsoft 365, SharePoint and digital organisation;
- governance, records, evidence and decision support;
- technical liaison between users, teams and decision-makers;
- responsible use of AI with human judgement and editorial control.

## Required public pages

The site should keep or develop these core areas:

- Home / first impression;
- About / personal context, kept professional and proportionate;
- Professional profile;
- Experience;
- Projects / workbench / case studies;
- Timeline;
- CV page or clear CV download route;
- Contact route;
- Privacy or contact-data note if a form is used.

## Content rules

Do not include:

- private employment dispute material;
- grievance material;
- medical information;
- personal financial information;
- third-party personal data;
- confidential employer, parish, client or community information;
- exaggerated claims about software engineering;
- Silicon Valley-style personal-brand fluff.

## Launch-ready criteria

Before the site is actively used in job applications, it should have:

- a clear homepage message;
- a focused profile and experience section;
- a small number of strong project examples or case studies;
- a safe contact route;
- a CV page or downloadable CV route;
- consistent navigation;
- checked spelling, punctuation and links;
- mobile and desktop visual review completed;
- no private or unnecessary personal material;
- links only to public projects that are safe and coherent.

## Current caution

Before changing public content, check the local VS Code working copy for uncommitted or unpushed changes. GitHub may not be the full current truth if work exists locally.
